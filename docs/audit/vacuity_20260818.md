## 1. Executive summary

### 1.1 What "vacuous" means here

Three distinct failure modes occur in this tree, and the catalogue keeps them separate:

1. **Ex falso** (Categories 1 and 2). A theorem whose proof term passes through
   `shiu_interface_contradiction : False` (`RH/Zeta85/Hypotheses.lean:161`). In Lean this is
   `False.elim` (written `h.elim` for `h : False`): from `False`, every proposition follows. Such
   a theorem type-checks, and `#print axioms` reports it as depending on `shiu_majorant` — the
   same report an honest conditional theorem would produce. The kernel cannot distinguish
   "conditional on X" from "derived from the refutation of X"; that is precisely why this written
   audit is needed.
2. **Unconstrained-existential interfaces** (Category 3). A `Prop` that existentially quantifies a
   witness (a "main term", a block family) and then imposes only constraints the witness can
   satisfy degenerately (zero error by choosing the whole sum; an empty block range by choosing
   `Dmax = 0`). The discharge theorems for these are *honest* — they prove exactly what the frozen
   statement says — but the statement itself carries no arithmetic content.
3. **Shadowed or unwired real results** (Category 4). Genuine proofs that exist in the tree but
   are not on the live path: the real support-`5/4` window cost is proved in a ~50-file module
   cone that nothing imports, while the wired declaration of the same statement is proved ex
   falso.

### 1.2 The single root cause

The frozen interface `ShiuMajorant` (`RH/Zeta85/Arith.lean:207-211`) quantifies its constants and
the height `T` **before** the interval scale `P`:

```lean
def ShiuMajorant (η : ℝ) : Prop :=
  ∀ (c : ℕ → ℝ) (Kc : ℝ) (k : ℕ), DivisorBounded c Kc k →
    ∃ C K T₁ : ℝ, ∀ T ≥ T₁, ∀ P : ℝ, 1 ≤ P → ∀ q r : ℕ, 0 < q → Nat.Coprime r q →
      (q : ℝ) ≤ P * T ^ (-η) →
      progressionSum c P q r ≤ K * (P / (Nat.totient q : ℝ)) * (Real.log T) ^ C
```

The right-hand side contains only `(log T)^C` — no `log P`. In the source
(`docs/run/12_arithmetic_cycle5_support_3over2_86p5674.md` §2 (14)) the scale `P` is polynomial in
`T`, so `log P ≍ log T`; the frozen rendering severed that coupling. With `T` fixed first, `P` may
grow without bound at constant right-hand side, and a divisor-function spike defeats the bound
(§2 below). Everything else in this catalogue is downstream of that one quantifier-order defect:
the axiom `shiu_majorant` (`RH/Zeta85/Hypotheses.lean:158`) asserts `ShiuMajorant η` for all
`0 < η < 1/2`, the tree refutes the instance `η = 1/4`, and the resulting `False` is then used —
deliberately and openly, per the consolidation's own records — to close interfaces and headlines.

## 2. The refutation itself: `not_shiuMajorant_quarter` is a real theorem

`RH/Zeta85/Discharge/ShiuNoGo.lean:28`:

```lean
theorem not_shiuMajorant_quarter : ¬ ShiuMajorant (1 / 4 : ℝ)
```

This is a genuine, self-contained refutation — Mathlib-only reasoning (the proof spans lines
28-141) with no axiom and no appeal to any other layer. It is a real mathematical contribution of the consolidated
tree: it identifies, in kernel-checked form, exactly why the frozen rendering of run-12 equation
(14) is not the Shiu/Brun–Titchmarsh bound it was meant to transcribe. The construction, step by
step (line numbers in `ShiuNoGo.lean`):

1. **Coefficient.** Take `c n := σ₀(n)`, the divisor-counting function (line 30). It satisfies
   `DivisorBounded c 1 1` — `|c n| ≤ 1·τ(n)^1` — definitionally (lines 31-33; `DivisorBounded` at
   `RH/Zeta85/Arith.lean:56-57`).
2. **Extract the constants.** From the assumed `ShiuMajorant (1/4)` obtain `C, K, T₁`
   (line 34). Freeze `T := max T₁ 1 + 1` (line 36) — from here on `log T` is one fixed number.
3. **Budget.** Set `B := K · (2T) · (log T)^C` (line 45) and pick a natural `m > max B 1`
   (lines 46-49).
4. **The spike.** Set `n := 3^m` (line 51): a single prime power whose divisor count is
   `σ₀(3^m) = m + 1` (proved at lines 106-110), i.e. the spike's height grows like `log₂ n`.
5. **The modulus.** Set `e := Nat.clog 2 n`, `q := 2^e` — the least power of two `≥ n`
   (lines 55-63); `q` is coprime to `n = 3^m` (lines 64-66).
6. **The scale.** Set `P := q · T` (line 68). The interface's range condition
   `q ≤ P · T^{−1/4}` reduces to `1 ≤ T^{3/4}` and holds (lines 73-84), so the majorant applies
   at `(T, P, q, r := n)` (line 86).
7. **Lower bound.** `n` itself lies in `[1, ⌈2P⌉]` and in the residue class `n mod q`, so the
   single term `p = n` gives `|c n| = m + 1 ≤ progressionSum c P q n` (lines 88-104;
   `progressionSum` is the plain absolute-value sum over the class,
   `RH/Zeta85/Arith.lean:202-203`).
8. **Upper bound is constant in `m`.** `φ(2^e) = 2^{e−1}`, so `q/φ(q) = 2` (lines 112-128) and
   the interface's right-hand side collapses to
   `K · (P/φ(q)) · (log T)^C = K · 2T · (log T)^C = B` (lines 129-136) — **independent of `m`**.
9. **Contradiction.** `m + 1 ≤ B < m` (lines 138-141).

The mechanism in one sentence: because `T` (hence `(log T)^C`) is frozen before `P` is chosen, one
may let the scale run away (`P ≈ 2^m·T`) while a power-of-two modulus of matching size
(`q ≈ P/T`) pins the normalized progression length `P/φ(q) = 2T` to a constant, and a single
divisor spike `σ₀(3^m) = m + 1 ≈ log₂ P` then outgrows the frozen `(log T)^C` budget. Any honest
correction must let the logarithm see the scale — `(log P)^C`, or constants uniform over a class
with `P` quantified before them; that is the `ShiuMajorant₂` redesign of the re-baseline (§8).

From the refutation, `RH/Zeta85/Hypotheses.lean:161-163` derives the layer's inconsistency in two
lines:

```lean
theorem shiu_interface_contradiction : False :=
  not_shiuMajorant_quarter
    (shiu_majorant (1 / 4) (by norm_num) (by norm_num))
```

`shiu_majorant` itself is the tree's only `axiom` declaration
(`RH/Zeta85/Hypotheses.lean:158`; confirmed by `grep -rn '^axiom ' --include='*.lean' Zeta23/ RH/
comparator/`, which returns exactly that one line).

## 4. Category 2 — vacuous by inheritance: rungs 101, 125, 143 and the 85 % corollary

The three "main line" rungs are **not** proved by writing `False.elim` at the headline. Their
derivations in `Main.lean` are genuine reasoning — the two-trace certificate algebra

premises those derivations consume out of the refuted axiom. Vacuous by inheritance, not by form.

## 5. Category 3 — vacuous-but-honest: the frozen BBLR interfaces

Two interfaces were "discharged" during consolidation. The discharges are correct proofs of the
frozen statements — no `False` is involved, and `#print axioms` on them shows only the standard
three. They are catalogued here because the *statements* have unconstrained existential witnesses,
so proving them transports no arithmetic content to the rungs. The tree's own docstrings say this
plainly; this section records the exact shape so a reviewer need not reconstruct it.

### 5.1 `BBLRErrorBound` — zero error by choosing the whole sum

Definition, `RH/Zeta85/Arith.lean:132-139`:

```lean
def BBLRErrorBound : Prop :=
  ∀ ε : ℝ, 0 < ε → ∃ Kε : ℝ, 0 < Kε ∧
    ∀ (α β : ℕ → ℂ) (W₁ W₂ W₃ W₄ wt : ℝ → ℂ) (A B M₁ M₂ N₁ N₂ H : ℝ),
      BBLRHyps α β W₁ W₂ W₃ W₄ A B M₁ M₂ N₁ N₂ H ε →
      (∀ x, ‖wt x‖ ≤ 1) →
      ∃ Mterm : ℂ,
        ‖bblrSum α β W₁ W₂ W₃ W₄ wt A B M₁ M₂ N₁ N₂ H - Mterm‖
          ≤ Kε * bblrErrorFactor A B M₁ M₂ N₁ N₂ H ε
```

The witness `Mterm` is an arbitrary complex number constrained only by the inequality it must
satisfy. Discharge, `RH/Zeta85/Discharge/BBLRErrorBound.lean:23-37`: choose
`Mterm := bblrSum …` itself (line 27), so the left side is `‖0‖ = 0`, and the published error
factor is nonnegative under `BBLRHyps` (`positivity`, line 37). BBLR Proposition 3.1's content —
that the *gcd main term* approximates the sum — is untouched, because the interface never says
what `Mterm` is.

### 5.2 `BBLRPoissonBlocks` — an empty block range

Definition, `RH/Zeta85/Arith.lean:155-163`:

```lean
def BBLRPoissonBlocks : Prop :=
  ∀ (α β : ℕ → ℂ) (W₁ W₂ W₃ W₄ wt : ℝ → ℂ) (A B M₁ M₂ N₁ N₂ H : ℝ),
    1 ≤ A → 1 ≤ B → 1 ≤ M₁ → 1 ≤ N₁ → 1 ≤ H →
    ∃ (Mterm : ℂ) (Dmax : ℕ) (blocks : ℕ → ℂ) (Klog Clog : ℝ), 0 ≤ Klog ∧
      bblrSum α β W₁ W₂ W₃ W₄ wt A B M₁ M₂ N₁ N₂ H
        = Mterm + ∑ d ∈ Finset.Icc 1 Dmax, blocks d ∧
      ∀ d ∈ Finset.Icc 1 Dmax,
        ‖blocks d‖ ≤ Klog * ((A * M₁ / d) * (B * N₁ / d + H / d)) * (1 + (d : ℝ)) ^ (-(2 : ℝ))
          * (Real.log (A * B * M₁ * N₁ * H + 3)) ^ Clog
```

Here `Mterm`, `Dmax`, `blocks`, `Klog`, `Clog` are all existential and essentially unconstrained.
Discharge, `RH/Zeta85/Discharge/BBLRPoissonBlocks.lean:23-29`: choose `Mterm := bblrSum …`,
`Dmax := 0`, `blocks := fun _ => 0` (lines 25-26). The decomposition reads `S = S + 0` and the
per-block bound ranges over `Finset.Icc 1 0 = ∅`. The Poisson-stage decomposition of the source
(run 12, (6)-(17)) is not assumed and not established.

### 5.3 Assessment

Both discharge modules state their own emptiness in their headers (`BBLRErrorBound.lean:8-14`,
`BBLRPoissonBlocks.lean:8-14`), as do the `Hypotheses.lean` wrappers (`Hypotheses.lean:92-95` and
`119-124`) and `AXIOMS.md` (lines 891-893, 905-909). Honest, then — but note the consequence for
the rungs: the "PROVED" premises `bblr_error_bound` (`Hypotheses.lean:97`) and
`bblr_poisson_blocks` (`Hypotheses.lean:126`) that `cert101`/`cert125`/`cert143` consume
contribute nothing; the entire arithmetic weight of every rung rests on the fabricated
declarations of §4.1. A reviewer should also note that the same unconstrained-witness pattern
appears, deliberately, in the *target* criterion `SignedPairTraceGrade`
(`RH/Zeta85/Arith.lean:193-197`), whose singular series `S : ℕ → ℝ` is existentially quantified —
a design choice documented at `Arith.lean:13-19` as making statements "weaker (hence safer)". No
degenerate witness for `SignedPairTraceGrade` is exhibited in-tree, so it is not classified as
contentless here; but the re-baseline should treat every existential in a frozen interface as a
potential content leak, because two of the three such existentials in this file collapsed.

### 8.2 Two proved obstructions that survive even a true Shiu bound

The audit emphasizes these because they bound what any fix can achieve; both are standard-three
theorems in the current tree, unaffected by the inconsistency:

1. **`RH.Zeta85.ActualScaleBBLR.progression_majorant_not_traceGrade`**
   (`RH/Zeta85/Discharge/ActualScaleBBLR.lean:197-203`): on the surviving symmetric
   `(2/5, 3/5)` block at `η = 43/100` (`eta`/`traceExponent` at lines 38, 41), the literal `d = 1`

   with logarithmic exponent zero (`source_lengths_exact`, lines 168-174; `progressionPQ_excess`,
   lines 184-188). A true progression majorant applied at these scales is a **power** short, so
   the run's route to rung 3 fails for a reason independent of the majorant's truth.
2. **`RH.Zeta85.LogBudget.verdict_all`** (`RH/Zeta85/Discharge/LogBudget.lean:275-280`): the
   trace normalization leaves room for `(log T)^C` only with `C < 2` in the most generous
   accounting (`budget_closes`/`budget_fails`, lines 162-178), `C < 1` under the literal dyadic
   triangle sum, `C < 0` fully triangle-summed; while the Heath–Brown depth forced at
   `η = 43/100` is `K ≥ 4` (`depth_at_85`, line 219), giving `C ≥ K − 1 ≥ 3`. All three
   accountings fail at `C ≥ 3`. Shiu-type bounds inherently cost positive powers of `log`, so

   route must first reduce the effective logarithmic cost below `C = 2` (cf.
   `crossScale_recombination_fails`, lines 287-289).

Consequently the honest re-baseline makes rungs 1-2 conditional on the block-closure and transfer
axioms only, and leaves rung 3 conditional on statements the tree itself proves are *not*
obtainable by the source's displayed method — which is the truthful state of the mathematics.
